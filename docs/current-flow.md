## 2. 产品资料从哪里来，最终以什么为准

### 入口与去向

| 入口 | 资料去向与注意事项 |
|---|---|
| 首页文字和附件 | 文字成为首条用户消息，也先放进产品卖点；系统自动给临时SKU，名称初始也用这个SKU，品类等先是待确认值。支持在首条文字写“SKU: 编号”。 |
| 新版对话、画布“上传”、拖入图片 | 上传到当前产品的资料列表；新版会接着触发识别。已有档案/方案确认会被重置，需要重新核对。选中或加入引用的画布图片则作为本次对话引用。 |
| 旧Agent页资料区 | 保存产品文件，并可手动把图片分类为实拍、白底、渲染、细节等；上传本身不会像新版一样自动做完整的品类识别。 |
| 产品资料表单 | “保存产品资料”写入产品基础字段和身份全文，并追加身份版本。 |
| 产品资料页“AI提炼” | 读已保存的商品字段和实拍，返回文本填到身份框；还要再点“保存产品资料”才生效，有内容被替换时先弹确认。 |
| 产品卡/Agent档案确认卡 | 先有会话里的档案草稿，人工确认后生成正式档案版本，并把身份特征写回产品。不是把所有产品基础字段都同步改一遍。 |
| 竞品截图、竞品链接 | 保存在产品的竞品输入下，规划时作为研究依据；不是当前产品的结构证明或自动附带的生图参考。 |
| 模板库 `/library` 的Listing导入 | 是品类经验的另一条支线，选择文件夹、审核后入经验库；不等于当前新品的产品资料，不会直接替当前产品填身份。 |

普通产品资料上传真正支持 JPG/PNG/WEBP、PDF、DOCX、XLSX、CSV；首页单批最多3张图片、15个文件、合计100MB，单文件最多30MB。首页能显示某个附件的名字，不代表服务端一定能解析，例如普通资料上传不支持TXT/JSON，Listing导入的可选TXT/JSON是另一套入口。

### 不存在一份简单的“最后输入就覆盖所有地方”

实际有四层：产品基础资料和身份全文、当前账号的Agent档案草稿、人工确认的正式档案、已经确认冻结的视觉方案。

1. 没保存的表单、没发送的文字、没确认的方案编辑，不能当成正式资料。
2. 规划时，analyzeProduct读取已保存产品字段、身份全文、实拍和已解析材料，再生成本次 identityLock；它不只是原样复制旧身份全文。
3. 用户确认方案后，身份、画面选择和实拍引用都被冻结。真正生图以该图位保存的方案快照为准，不是在出图瞬间重新拼“当前所有输入”。
4. 生成任务又保存自己的输入快照，供历史核对；修改图片优先沿用原图任务的身份及原始实拍，不自动改用用户后来输入的新身份。
5. 上传资料会使会话的档案/方案确认失效；但旧产品资料的普通保存与档案确认不是同一套同步动作。改了商品字段，不能假定旧档案草稿或已冻结方案也自动更新，应该重新核对并冻结。

### 对话引用图：任务13-2已接通（原12-B缺口）

在对话上传图片，或选画布图片点“加入对话引用”，图片会送给Agent。Agent先区分产品实拍、编辑原图与参考图；参考图必须明确只参考光线、构图、场景、色调、道具等哪些方面。分不清时问一句普通话，不弹卡片。用途跨轮保存。首页第一次识别也区分产品与参考，不再把全部上传图当产品实拍。

出方案时每图位绑定0–2张参考图，图位卡里显示缩略图、用途、移除和从当前对话替换的选择；确认方案后和身份锁一起冻结。报价与生成读取同一份快照，不能靠后来修改对话用途悄悄改变已经冻结的图位。

生图实际传入产品实拍和该图位的参考图，不只是文字描述。提示词按输入顺序解释每张图的用途：产品图锁定外观/结构/颜色/材质，参考图只借鉴指定方面，不能把参考图家具搬进画面。超限优先保留产品实拍，再按顺序保留参考图；编辑还必须保留原图和蒙版。未知/不支持多图的模型明确报错，不退化成文字参考。

修改与再来一张默认沿用原图实际使用的参考图，用户明确指定新图时替换。完成后选中画布图，展开像素/费用旁的参考信息可看到实际参考缩略图和用途、上限及省略记录；旧图包看板也可查看。历史任务没有这份元数据时不冒充它用过参考图。

## 4. 从对话到真正生图，要确认几次

先区分：**请求下一步的按钮，不算正式确认；真正保存资料、冻结方案或批准费用的按钮才算。** 如果用户把所有点击都算进去，会比下表多。

### 新版第一次做新品：通常4道正式确认

| 次数 | 确认内容 | 用户实际点击 |
|---|---|---|
| 1 | 产品品类 | 品类卡“是”或换一个品类 |
| 2 | 正式产品档案 | 先点“核对产品档案”打开卡，再点“确认并保存档案”；在产品卡抽屉保存档案也是同一目的 |
| 3 | 视觉方案 | 给有选项的图位选方向，最后点“确认并冻结方案” |
| 4 | 实际生图费用 | 先点“生成候选 · 先查看费用”取报价，再在费用卡点“确认并生成” |

品类要求严格拍摄时，还多一次“按严格来 / 这次先快速”选择，所以通常变成5道；缺拍摄项时可能还要点“先跳过”。关键图位的方向选择、Agent的问题回答、解决资料冲突、重新报价确认，都可能继续增加点击，不能给所有产品一个固定总点击数。

如果完全走新版阶段按钮，除上述4道确认外，还包括首页发送、“核对产品档案”、“规划图包”、“生成候选 · 先查看费用”4个触发动作；有方向选项再逐图位点选。Agent直接给出某张卡时，相应的触发动作可能省掉。

### 其他路径的确认数不同

| 路径 | 当前行为 |
|---|---|
| 旧Agent页按正常理解→方案→生成走 | 通常3道：确认产品档案、确认方案、确认费用；没有新版单独的品类卡。问题回答另算。 |
| 旧商品页“规划一张场景图” | 通常2道：确认方案、确认生图费用；已有手工身份资料，并可在确认方案时补建正式档案。 |
| 产品/方案已经确认，再追加生成 | 不重新做新品档案确认；通常再看一次费用卡。 |
| 旧看板点批量生成或单图位再来几张 | 先点生成取报价，再在“确认生成候选图”弹窗点“确认并生成”；服务端仍要求有效的冻结图位。 |
| 对话要求整图修改 | Agent创建费用卡，再由用户确认；局部修改会先要求到画布做蒙版。 |
| 画布换背景、抠图、再来一张 | 通常点动作后出现一次浏览器费用确认；确认才提交。 |
| 画布局部重绘、消除、扩图 | 先在编辑器点“确认 · 约 $…”提交选区/范围，再出现浏览器实际费用确认，是两次确认动作。 |
| 新版失败节点“重试” | 当前直接重新报价并提交，没有另弹一次费用确认卡或浏览器确认框。 |
| 旧商品页历史里的“生成编辑版本” | 编辑面板内显示估价，点按钮直接提交，没有独立的第二次费用确认弹窗。 |

旧Agent页可以开启“自动确认≤$1”，默认关闭；首轮/首批仍须手工确认，后续只有符合条件的费用操作才可能自动通过。新人流程的品类、档案、方案不能因此自动代确认。

**生图费用卡不是所有AI费用的总开关。** 首页后的自动识别、发送对话、AI提炼、规划、竞品看图、按意见重写、标记优秀等，可能在这张卡之前就调用模型；旧Agent确认卡后自动继续，也会产生额外对话调用。

## 5. 图出现在哪里，选中后能做什么

### 出现位置

- 新版 `/workspace?sku=…`：右侧画布按图位展示候选；原始实拍在单独一组，候选带真实像素角标，长边不足2000px会显示待处理。
- 旧 `/products/[id]/pack`：ImagePackBoard的图位候选区；可以放大、选终稿、下载、对话调整和重试。
- 产品资料 `/products/[id]`：下方生成历史，包含图包图与旧记录；可看模型/网关、费用、任务编号、身份快照、下载及二次编辑，不只展示一种来源的图片。

### 新版选中一张候选

| 操作 | 用户步骤与结果 |
|---|---|
| 放大查看 | 双击图片或点放大图标，打开原图预览；不调用模型。 |
| 设为终稿 | 点击后直接记录该图位终稿，不再多一张确认卡；通过对话要求设终稿，则会先出现终稿确认卡。 |
| 加入对话引用 | 当前图片加入对话参考；选中图片本身也会进入本次引用集合，最多6张，过多时不能发送。它不等于已传给生图模型。 |
| 局部重绘 / 消除 | 框选或涂抹蒙版、填写修改要求，点编辑器确认，再确认费用；生成新候选，原图保留。 |
| 扩图 | 调整画面比例或拖动扩展范围，点编辑器确认，再确认费用。 |
| 抠图 / 换背景 / 再来一张 | 调用对应修改要求，先弹费用确认；“再来一张”针对已有图片也走修改路径，不是删除原图重建。 |
| 标记优秀 | 要先设为终稿；点击后AI分析实际终稿，生成案例/经验确认卡，再点“确认入库”才写进模板库。不是免费手动收藏。 |
| 下载 | 下载原图文件，不调用模型，不要求先设终稿。 |

原始实拍只显示“加入对话引用 / 下载实拍”等普通操作，不和生成候选共享全部工具。多选候选时切换成“对比 / 批量下载 / 删除”；这里的“删除”是从当前画布布局移除，原图、历史任务和终稿仍保留。

### 修改、回退和保存

- [version-history.tsx](C:/Users/Administrator/Projects/furniture-ai-studio/src/components/design-preview/version-history.tsx)显示“修改版本 · 对比与回退”，能看修改前后，也能将旧候选重新设为终稿；回退是切换终稿选择，不会删掉后面的版本。
- 生成和修改结果会自动存到系统；选终稿是另一个明确保存动作；下载只是存到用户电脑。这三件事不是同一个按钮。

- 普通、无AI的“手动收藏到素材库”仍没有独立完成的入口；当前能用的是下载、选终稿、对话引用，以及会调用AI的标记优秀。

## 6. 重复、绕路和容易卡住的地方

以下是源码能确认的行为或由这些行为带来的使用风险，没有在本任务中修改，也没有用模型实测。

1. **两套工作台并存，入口很绕。** 想用旧Agent的手动模式、详细资料分类，要从新版产品卡跳产品资料，再跳旧图包页；想做局部蒙版又要回新版。两页确认后是否自动继续也不同。
2. **资料有多份，改完不一定用到。** 产品资料、档案草稿、正式档案、冻结方案、原图任务快照都存在；普通保存商品字段没有把这些层全部同步。对已有图改身份时，用户容易以为“保存资料后再生成”必然用了最新值。
3. **产品理解重复。** 首页自动识别一次，聊天可能再读图、核对一次；规划又会用 analyzeProduct分析一次身份。用户已确认资料后仍可能感觉被重复问、重复看图，而且前置模型调用不在生图费用卡里确认。
4. **新版需要自己推动多个阶段。** 档案确认后常要再点“规划图包”，方案确认后再点“生成候选 · 先查看费用”，不像旧Agent确认卡后会自动继续；用户容易误以为卡片确认后没反应。
5. **方向、拍摄、缺失信息可能层层叠加。** 方向未选不能冻结；档案存在冲突不能确认；严格模式还有缺图提示；费用不足、worker离线、照片被删除或快照失效又会拦住下一步。这些是不同关口，不是一个“出图按钮”。
6. **单张入口名字容易误导。** 产品资料页点击“规划一张场景图”会离开当前页去新版方案卡；旧图包页仍能手填图位，但缺少冻结快照又不能真的生成。用户可能走了更长的路，仍回到方案确认。
7. **引用图与真实生图未贯通。** 对话里能看图、画布也显示引用，不代表生图会参考它；这是12-B最直接的接线缺口。历史消息里的引用缩略图目前也没有点击后定位画布节点的事件。
8. **费用确认不统一。** 普通生成走卡片，普通画布修改走浏览器弹窗，局部/扩图先确认编辑器再确认费用；新版失败重试和旧商品页编辑则直接提交。不能告诉用户“任何调用都有同样的最后确认”。
9. **“保存”“删除”“收藏”含义不同。** 自动保存的是布局和系统图片，终稿另选，画布删除只隐藏；“标记优秀”是AI提炼入库，并非普通收藏。名字相近，但实际后果差很大。
10. **上传入口规则不统一。** 首页最多3张图片；旧实拍管理总共最多3张；资料上传可收更多类型的补充图片，但起初未必是生图实拍。TXT/JSON在首页可先显示附件名，却会被普通资料解析拒绝；Listing导入又允许其作为参数文件。
11. **更换资料会让旧确认失效。** 在工作台补图会重置档案/方案确认，新版还会重新识别品类；用户原以为只补一张细节图，可能需要重走几张卡。若识别失败、图仍未正确分类，规划又会提示没有实拍。
12. **同一产品换入口或换模式会卡住。** 新版“生成候选”固定请求整批；如果之前在旧Agent把会话切到手动模式，服务端会拒绝整批，要求逐图位或切回快速。新版没有同样显眼的模式切换控件。
13. **库与竞品入口虽在，联网不一定成功。** 联网还受会话选择、GOOGLE_SEARCH_ENABLED、所选模型和上游能力限制；竞品网页链接也不保证能读到图片。页面能点，不等于这次研究一定有有效来源。
14. **错误后的继续方式不一致。** 新版“刷新进度”、旧Agent“继续”、节点“重试”、画布布局“重试”解决的是不同问题；不应把它们都理解成重新出图。
15. **新版多问题卡可能无法提交。** Agent工具允许一张卡有1～3个问题，但新版 RealCard只显示第一题选项，也只交一个答案；服务端要求答案数量等于问题数量。出现多题卡时会报“请回答全部问题”，只允许自由填写、没有选项的题也缺少卡内输入框；旧Agent页会逐题显示。这是源码可确认的界面与校验不一致，不只是等待模型。
16. **新版档案卡不方便处理已有冲突。** 新版 ProfileForm只有字段输入，改字时仍保留原冲突记录；服务端又不允许带冲突确认。旧Agent档案卡有“我已核实，以上填写值为准”的控件，新版没有同样入口，所以有冲突的档案可能要回旧页核实，或通过对话重新更新草稿，不能只反复点保存。
