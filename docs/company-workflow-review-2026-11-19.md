# 跨境电商团队使用审查 · 2026-11-19

**适合家具电商小组试点，暂不适合作为多人常态交付和公司知识沉淀的唯一工作台。** 从实拍到生成、改图、选稿、ZIP 导出已经可用。老同事也能保存图片提示词，已审核的品类经验会进入后续策划。主要差距在三处：下一个人如何接手，做好的成果如何共享，以及哪个经验确实减少了返工。

评估以一家公司内的家具团队为前提，沿着新人处理新品、美工交给运营、下一个相似 SKU 复用旧成果三条路径进行。本文的优先级以公司试点为目标；团队协作限制与已存在的功能故障分别说明。

## 一次真实团队任务会经过什么

| 环节 | 目前能做 | 员工会在哪里卡住 |
| --- | --- | --- |
| 接到新品 | 首页拖实拍及资料，选择套图，也可走独立工具 | 套图卡打开文件选择，选完仍要在首页发送。没有显式的业务 SKU 或交付目标选择，首次使用难判断是否已开始 |
| 确认产品 | 可识别、区分实拍和风格参考、核对资料与身份 | “确认产品”“核对产品档案”“规划图包”分布在对话流。看得见处理记录，但没有持续显示的任务阶段、当前卡点和下一步 |
| 生成与调整 | 可编辑方案、逐图选参考、独立生成、比较版本、局部修改、选终稿 | “生成候选”覆盖当前确认方案里的已定稿图位；输出中需要后期的底图和可交付终稿缺少状态区分 |
| 运营审核与导出 | 有独立评审页、逐图位评分、历史轮次、ZIP 和审计清单 | 工作台没有直接送审入口。批准哪张图、谁接手和能否完整导出没有统一状态 |
| 复用与积累 | 个人图片模板可手动复用；审核入库的品类经验可供 Agent 策划 | 收藏模板默认只在本人账号；评审未绑定具体版本，下一次检索不读取采用和返工信号 |

## 优先修复或补齐

| 优先级 | 发现与依据 | 改到什么程度算可用 |
| --- | --- | --- |
| P1 · 交接 | **同一 SKU 的资产共享，确认和交班上下文分散。** 双账号实际验证，美工 A 已确认方案并选好终稿，运营 B 能看见终稿，自己的会话无 A 的对话和确认，继续套图仍被要求确认。原画布布局保存在个人会话。缺少明确的项目负责人、待我处理、交接说明和送审入口。见 `src/lib/agent-state.ts:8`、`src/lib/agent-actions.ts:23` | 将已确认的产品档案、当前方案版本、完成状态、交接备注和审核结果归到项目。私人对话、草稿及视口保留个人属性。B 从项目接手后直接看到当前状态、已选图、待办和来源，不需重复确认已经冻结且未变化的同一方案 |
| P1 · 交付 | **临时试图能改变整套图包的交付状态。** 已完整导出的图包，向同一项目提交一次独立单张后，新增图位没选终稿，完整导出被拒。界面也会禁用“下载 ZIP”，需要打开“仅导出已有终稿”。图包导出扫描全部有效图位。见 `src/lib/direct-image-generation.ts`、`src/lib/pack-export.ts:8`、`src/components/design-preview/live-workspace.tsx:188` | 明确区分交付清单和试验图。整套导出按当前交付清单判断完整性；试验图由人明确加入才计入进度和 ZIP。保留已有项目、图位和历史图片 |
| P1 · 后期 | **尺寸图、卖点图可以规划成待后期底图，但缺少把外部完成稿放回同一图位的交付路径。** 方案有后期说明，生成刻意留白不渲染尺寸和文字。导出清单没有专门的后期待办字段；在本地用上传资产尝试设终稿，被服务端“只能选择该图位已生成的候选图”拒绝。见 `src/lib/visual-plan-rules.ts:69`、`src/lib/image-packs.ts:51`、`src/lib/pack-export.ts` | 图位分别支持生成底图、上传后期成品、审核通过。运营能看到待核对的尺寸/文案、原稿与成品关系。实际必交图未完成时明确列出，临时图不影响 |
| P1 · 团队资产 | **收藏能积累个人模板，不能自然形成公司共享的图与提示词。** A 收藏后，B 列表查不到，拿模板 ID 也不能复用。收藏不进 Agent 自动检索。另一路“标记优秀/历史 Listing 导入”可以产出共享品类经验，本次用人工确认的模拟条目验证了确实可检索。见 `src/lib/saved-references.ts:14`、`src/lib/visual-planning.ts:63`、`src/lib/agent-actions.ts:157` | 收藏默认仍是个人。新增有权限的“提交为团队模板 → 审核发布”路径。发布版本保留来源终稿和用途，其他成员可只读使用、派生或提交新版，原有个人收藏不会被自动公开 |
| P1 · 采用与复盘 | **评分能留档，无法说明哪张图被采用、哪个模板更有效。** 同图位两位成员评分保留两条历史，汇总按最后一条。评分只绑定轮次和图位，候选版本不在评分键里；后续经验检索不读取评分或复用结果。当前评审适合一人给每图位作结论，不能直接当作多人版本审批或效率报表。见 `prisma/schema.prisma:520`、`src/lib/review-scoring-rules.ts:12`、`src/lib/visual-plan-rules.ts:57` | 送审时锁定候选版本。能区分成员意见与最终结论，记录采用图、返工原因、审核人，以及引用的模板版本或品类经验。把证据用于团队模板维护和推荐 |
| P2 · 新手入口 | **任务入口的下一步不一致。** 套图卡点击后只是备好要求并打开上传，选择实拍后仍留在首页，未创建任务；其他工具直接进入操作页。“继续上次的创作”打开全部 SKU 列表。浏览器检查确认。见 `src/components/design-preview/home.tsx:38` | 首次套图流程按“添加实拍 → 确认产品 → 确认方案 → 生成候选 → 选择/送审”提供一个明显主按钮和返回路径。首页把真正的最近项目与“查看全部”分开。默认预设推荐项，模型参数按需展开 |
| P2 · 从模板建新品 | **先看好模板再创建新品仍得绕回首页。** 模板弹层只让选已有产品，空列表不能上传实拍。套图首页会从描述识别特定格式的 SKU，否则生成临时编号。真实 SKU、品类、市场等维度缺少统一的显式起点。见 `src/components/design-preview/saved-references.tsx`、`src/lib/studio-main.ts:46` | 模板入口直接给“用在已有产品 / 用这个模板新建产品”。新品填真实 SKU 或留草稿，冲突时引导返回已有项目。预选模板带到新品，仍需核对实拍、产品事实和模板借鉴范围 |
| P2 · 避免重复生成 | **默认整套生成会把已有终稿的图位计入。** 对只有一个已定稿图位的已确认方案，实际调用报价仍返回 1 张；未提交生成。这可以用于有意重新探索，但缺一个更省时的默认范围。见 `src/lib/image-packs.ts:100`、`src/lib/pack-rules.ts:21` | 默认只补未完成、缺候选或明确选择重做的图位。“生成更多候选”“整套重做”作为明确选项。数量按实际计划范围显示 |
| P2 · 入库界面和兼容 | **独立单张设为终稿后，仍不能走优秀案例提炼。** 操作在生成图菜单里可见，但服务端要求图位有预先冻结的视觉方案，独立图位没有该快照，实际返回字段校验错误。正常案例确认与品类经验详情直接展示 JSON，审核容易变成走过场。见 `src/lib/visual-case.ts:11`、`src/components/design-preview/live-workspace.tsx:173`、`src/components/design-preview/pattern-library.tsx:15` | 明确“个人收藏”和“申请团队入库”的区别。对可用的独立图提供填写用途和适用范围后再入库的路径；审核界面展示来源图、可借鉴点、不要照搬的点和修改记录 |
| P2 · 项目检索与职责 | **真实 SKU 列表不能按待办找项目。** 当前正式页只列名称、SKU、品类和删除入口，没有关键词、负责人、待审/待后期筛选。通用写权限主要排除只读成员，模板编辑员、设计师、运营审核的业务职责未分开。见 `src/components/design-preview/live-workspace.tsx:193`、`src/lib/studio-api.ts` | 先实现按 SKU 搜索、我的任务、待审队列。将策划/制作、审核发布及项目管理的权限单独定义。是否需要按品牌/部门隔离，应由实际组织方式决定 |
| P2 · 经营与上线准备 | **现有 ZIP 是创作交付件。** 有像素、顺序和模型记录，也明确缩放不增加真实细节。没有可执行的店铺/站点、语言、品牌、变体交付预设及上线检查。README 的运行步骤主要面向本机，团队生产的备份恢复、监控与访问边界需在实际部署时验收。见 `src/lib/pack-export.ts`、`src/lib/ui-features.ts`、`README.md` | 从团队实际使用的一条渠道、一个站点做起。约定必交图、尺寸比例、目标语言、文案与卖点来源、颜色/尺寸对照和运营人工核对。用备份恢复演练与任务监控验证共享服务 |

## 怎样让越做越快成为可检验的结果

1. **先让交接和交付可重复。** 主入口只做一条新品主线。每个图位有明确状态和责任人，发送哪个版本审核、要补做什么、何时可导出一目了然。将试验图从商品交付范围中分离。
2. **只把通过审核且可复用的经验发布给团队。** 建议第一期只存来源终稿、适用品类/图位、可复用画面做法、不可沿用的产品事实和模板版本。先覆盖同一品类常见的两三类任务，例如白底图、门厅场景、细节卖点。涉及图片使用范围的参考素材保留来源标记。
3. **新项目优先推荐少量有依据的旧经验。** 目前检索按品类名、固定相近品类和卖点字符串匹配，最多返回 40 条，既不会按采用情况排序，也不会因积累自动提高命中率。建议先按“已发布、相同品类与图位、有经确认的采用记录”选少量结果，显示推荐理由。设计师能跳过，新增经验也能通过人工审核获得使用机会。
4. **用通过审核的交付衡量产出。** 保留原提示词和模型记录，增加模板版本、首次送审版本、审核决定、返工原因和交付时间。运营纠错应先沉淀为可审核的规则，例如“这类玄关桌容易多生一层横梁，侧面层数以实拍为准”，不把某款 SKU 的具体结构强加给全品类。

| 试点指标 | 建议记录方式 |
| --- | --- |
| 新手独立跑通 | 给新人实拍和任务要求，观察是否能独立完成第一套送审；记下卡住的按钮或术语，不把待模型时间当成界面耗时 |
| 单 SKU 做图效率 | 记录从资料齐全到送审的时间、美工实际操作时间、从送审到批准的时间 |
| 首轮采用和质量 | 按首次送审的具体图片版本统计“直接采用 / 小改 / 重做”；未评单列。分开看主图、场景和细节，记录具体错误类别 |
| 返工与成本 | 每套批准图包的生成次数、重做次数，以及可归属的生成和规划费用，区分预估与已结算 |
| 模板复用价值 | 记录哪一版模板被用于哪个图位，以及该图位最终的审核结论。以同品类、相同交付要求和相近难度的小批 SKU 比较使用模板与不用模板的结果 |

试点建议选一个类目、一条交付规范，由新人、美工、运营完成约 6–10 个 SKU。旧图复用的目标是操作时间或返工次数下降，首轮采用率与商品事实准确性保持。真实人员可以完成交接、审稿与导出后，再扩大到其他类目和市场。

## 本轮验证

- 复查了正式首页、工具页、图包工作台、SKU、个人模板、品类经验、评审、导出、角色和模型记录。23 项既有隔离浏览器回归通过。
- PostgreSQL 和 MinIO 的临时双账号测试验证了团队交接、收藏边界与共享经验检索、已完成图位再次计入报价、独立图影响完整导出、独立图案例提炼失败、多人评分聚合及上传素材无法直接设终稿。生成提交使用模拟队列，测试记录与对象已清理。
- 4 项专项浏览器检查通过。使用正式组件和模拟接口，分别确认套图上传后的状态、模板新品入口的限制、另一账号的工作台和独立图位对导出按钮的影响。使用 `.local/company-audit.ts`、`.local/company-usability.spec.ts` 与对应日志可复查该轮证据。
- 本轮没有业务代码变更。复现使用隔离数据及模型模拟，产图质量、新人的实际完成时间和经营成效留待团队小批量试点确认。
