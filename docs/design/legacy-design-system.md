# 任务 7 · 界面设计规范

状态：第一阶段设计提案，等待用户确认。适用对象：家具电商团队的美工与管理员。现有业务页面尚未迁移。

## 设计方向

保留现有墨绿品牌色，用暖白操作区、浅灰画布和大尺寸图片建立专业创作空间。美工先看到产品与作品，再看到下一步操作；Agent 像共同创作的伙伴，问题、方案、费用和确认动作都融入对话。

全局只保留项目、模板、素材与管理入口。产品资料与图包归入同一个 **SKU 工作台**，不再让美工在两个业务页之间切换。

## 组件规范

所有交互组件统一使用 **shadcn/ui**，沿用本项目 `base-nova` 风格及 Base UI 实现。不得裸露浏览器原生 Select、Checkbox、Switch、Dialog 或文件选择框；不得用没有按钮外形、交互反馈与焦点状态的文字代替操作按钮。

| 使用场景 | 组件与约定 |
| --- | --- |
| 主要操作 | Button 实心墨绿，必要时配 lucide 图标；每个区域最多一个视觉主操作 |
| 次要操作 | Button outline / secondary；ghost 用于工具栏轻操作与图标操作 |
| 链接按钮 | Button `render={<Link />}`，设置 `nativeButton={false}`，保留链接语义 |
| 单选 / 排序 / 筛选 | Select，不使用裸 `<select>` |
| 多选 / 确认 | Checkbox，每个选择项都有清楚的标签 |
| 开关 | Switch，标签解释开关后的结果 |
| 快速 / 手动 | Tabs 的 Segmented 外形，选中态明确，可键盘切换 |
| 分组内容 | Tabs，选中项用底色或下划线，不仅改变文字颜色 |
| 轻量确认 | Dialog，包含标题、说明、取消和确认按钮 |
| 产品档案 / 图位设置 / 图片详情 / 用户编辑 | Sheet，右侧抽屉；关闭、焦点恢复和 Escape 由组件处理 |
| 更多操作 | DropdownMenu，破坏性操作与普通操作分组 |
| 图标说明 | Tooltip，图标按钮另提供中文 aria-label |
| 操作反馈 | shadcn Sonner（Toast），成功、失败和提示采用统一样式 |
| 加载 | Skeleton；图片生成中采用带轻微动画的占位卡 |
| 状态 | Badge，文本与色块同时表达含义 |
| 后台 | Table，筛选工具栏 + 行操作 + 侧边编辑抽屉 |
| 输入 | Input / Textarea / Label；文件 input 隐藏，使用附件按钮与拖拽区触发 |

新增组件在 `src/components/ui/`。第一阶段仅设计稿引用新增组件，既有组件未被替换。图标统一为 `lucide-react`，不得混用 emoji、文字字符或多套图标库表达产品操作。

## 字体与层级

中文使用本机 `Microsoft YaHei UI / PingFang SC`，英文与数字使用 `Segoe UI`；无需下载字体，中文与金额保持清晰。数字采用等宽数字排布。正文不得小于 **14px**，辅助文字不得小于 **12px**。

| 层级 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| 页面标题 | 28–30px / 600 | SKU 项目、用户管理 |
| 区域标题 | 22–24px / 600 | 商品图包、抽屉标题 |
| 产品名称 | 17–18px / 600 | 项目卡、SKU 顶栏 |
| 正文 / 核心输入 | 14–16px / 400–500 | 对话、问题、输入、档案内容、表格主字段 |
| 辅助信息 | 12–13px / 400 | SKU 编号、来源、时间、状态补充 |
| 金额 | 18–30px / 550–600 | 本次花费、后台用量 |

正文与关键操作使用深色。灰色只用于来源、时间、提示、占位等次要说明，不把重要问题、费用确认或可执行操作变成浅灰小字。浅色用于装饰、禁用与骨架，不用于需要阅读的正文。

## 间距、圆角与层级

采用 **8px 基础栅格**，主要间距为 8 / 16 / 24 / 32 / 40px。4px 用于图标、紧凑标签与细节对齐；禁止各页面临时发明不一致的间距系统。

控件圆角 8px，按钮 8–10px，图片与卡片 12–14px，确认弹窗 16px。图片裁切到卡片边界；主图按合适比例展示，查看详情时可看原图，不为填满卡片而永久修改文件。

卡片默认使用 1px 边框及轻阴影 `0 2px 4px #233A2410`，悬停使用 `0 10px 28px #233A2417`。被选中的图位采用墨绿边框及淡绿外圈。抽屉使用更高层级阴影，避免所有面板都同样抢眼。

标准按钮高度 38–40px，输入高度 40–42px；图标按钮 32–36px。表格行保留充分上下间距。焦点状态清楚可见，所有图标操作具有中文名称。

## SKU 项目列表

桌面使用三列卡片网格，中等屏幕两列，手机单列。卡片包括大主图、SKU、名称、状态、`5/7 图位已完成`、最近更新人和时间；图片本身可以打开工作台。

搜索与“全部 / 进行中 / 已完成”筛选放在网格上方。最近更新排序为默认；更多操作收进 DropdownMenu，不在图片旁堆砌文字按钮。空结果显示明确说明与恢复全部项目操作。

## SKU 工作台

- 顶部条：产品名称、主图缩略图、理解度圆环、产品档案入口、快速 / 手动 Segmented、本次花费、导出按钮。
- 左侧对话：桌面宽度约 32%，可折叠；消息流独立滚动，底部输入固定。消息气泡、问题选项卡、确认卡与工具执行状态形成自然阅读顺序。附件支持拖拽、文件选择与粘贴。
- 中间画布：大缩略图优先显示终稿或最佳候选；图位卡只放名称、场景意图和状态。设置收进 Sheet，避免每个图位变成大表单。
- 提问状态：展示参考实拍与待生成方案卡，明确“尚未生成”，不能把参考图误称为候选。
- 调整状态：已生成图位置于上方，当前图位用边框突出；候选在同一行比较。悬停 / 键盘聚焦时出现“设为终稿 / 和 Agent 调整 / 再来一张 / 详情”。手机保留可见的主要操作。
- 人工图位：还没有图片时使用简洁占位与待制作标签，已有人工图片后恢复大缩略图，不默认显示编辑表单。
- 产品档案：结构化字段卡片，每项带“已确认 / 推测 / 缺失”及来源；不使用一个覆盖全部资料的大文本框。
- 批次进度：仅生成期间显示顶部低对比提示；完成后自动收起，结果由 Toast 与新候选呈现。历史进入“生成记录”抽屉。
- 旧档案候选：在对应图片上标“待核对”，详情说明变更及“核对后保留 / 按最新档案重做”。不得用一个全局警告代替逐图定位。

手机上下排列对话与画布，保留固定在对话区底部的输入。此阶段仅演示布局与本地交互，不实现生成、档案同步或自动进度监听。

## 管理后台

用户、模型、网关、用量沿用相同的管理导航、搜索筛选工具栏、标准表格和侧边编辑抽屉。用户表格优先显示成员、中文角色、账户状态、月度花费 / 额度及最近登录。

“清理测试数据”单独放在后台导航底部，与成员编辑和生产操作分开。实际清理功能需定义筛选预览与二次确认；本设计稿只展示入口，不删除数据。账户停用开关为设计提案，接入时需确认现有数据模型及会话撤销语义。

## 文案与技术信息

界面使用美工能理解的中文，例如“创作搭档”“再来一张”“保持产品外观”“这张图想表达什么”。品类、复杂程度、模式等技术枚举不得直接露出 `simple`、`ai_scene` 等内部值。

provider、model、批次 ID、身份版本号等默认隐藏；图片的“详情 → 技术记录”或管理后台可以查看。对外主视图使用“产品档案已更新，需要核对这张图”，无需先读懂版本号。

金额最多保留 **2 位小数**，例如 `$0.15`。实际、预估、预留分别表达；小于 `$0.01` 的非零费用用“小于 $0.01”，避免让人误以为未收费。后端精度不因显示四舍五入而改变。

费用必须标明范围：“本人本次会话”“这个 SKU 的累计花费”“本月团队用量”不可混为同一数字。第一阶段顶部用假数据展示“本次花费”，实际范围的修复见任务 7 排查报告。

## 交付边界与实现位置

设计稿：`src/app/design/` 与 `src/components/design/`；样图：`public/design/`；截图和说明：`docs/design/`。样式仅挂在 `.d-scope / .d-*` 命名空间，门户弹层也附加设计作用域。

未改现有业务页面、服务端接口、生成队列、Prisma 模型、权限规则或根样式。`/design` 继续使用原有登录保护，静态用户管理页不读真实成员资料。所有保存、生成、上传和导出仅为本地预览，不调用业务 API。

确认设计后才开始第二阶段迁移与 bug 修复。
